## Positioning

**PeekabooWin: A Trusted Visual Desktop Automation Runtime for Windows Agents**

PeekabooWin provides a safe, observable, and recoverable execution layer that any LLM-based Windows agent can call into. V0.14 closes the integration gap by wiring `ActionVerifier` and `RecoveryPlanner` directly into the `AgentOrchestrator` execution loop, formalizing the `ExecutionTrace` model, and exposing a versioned Agent Runtime API.

## V0.14 Changes

### 1. AgentOrchestrator Integration

The `AgentOrchestrator.RunAsync` loop now integrates `ActionVerifier`, `RecoveryPlanner`, and `ExecutionTrace` as first-class pipeline stages:

| Stage | Component | Role |
|-------|-----------|------|
| 1 | `ElementCandidateRanker` | Score and rank candidate elements |
| 2 | `ActionExecutor` | Execute the top-ranked action |
| 3 | `ActionVerifier` | Before/after verification of action effect |
| 4 | `RecoveryPlanner` | Plan recovery when verification fails or action throws |
| 5 | `ExecutionTrace` | Record full trace with risk, verification, recovery, and candidate data |

On successful action execution, `ActionVerifier.VerifyAsync` is called to confirm the action achieved its intended effect. On failure, `RecoveryPlanner.PlanRecovery` generates a recovery plan and the orchestrator executes recovery steps, then re-verifies.

### 2. ExecutionTrace Model

The `ExecutionTrace` model captures the complete lifecycle of a task execution:

```
ExecutionTrace
├── TraceId                  Unique trace identifier (trace_yyyyMMdd_HHmmss)
├── Task                     Original task description
├── StartedAt / CompletedAt  Timing boundaries
├── Success                  Overall success flag
├── ParserMode               "rule_based" | "llm" | "none"
├── LlmEnabled               Whether LLM was used for planning
├── FallbackReason           Reason for parser fallback
├── Decision                 "ALLOW" | "BLOCK"
├── RiskLevel                "L0" | "L1" | "L2"
├── GroundingScore           Best candidate grounding score (0.0–1.0)
├── StepTraces[]             Per-step trace records
│   ├── RiskGateTrace        Risk gate decision, score, block reason
│   ├── VerificationTrace    Verification status, reason, confidence
│   ├── RecoveryTrace        Recovery strategy, should-retry, step count
│   └── CandidateRankTrace   Total candidates, best score/text/source
├── TotalSteps / SuccessfulSteps / FailedSteps / BlockedSteps
├── RecoveryAttempts         Number of steps that triggered recovery
├── Cancelled / TimeoutTriggered
└── Error                    Terminal error message
```

**Sub-trace models:**

| Model | Fields | Purpose |
|-------|--------|---------|
| `RiskGateTrace` | Decision, RiskScore, BlockReason, RequiredConfirmation | Risk gate evaluation result |
| `VerificationTrace` | Status, Reason, Confidence | Before/after verification result |
| `RecoveryTrace` | Strategy, ShouldRetry, RecoveryStepCount | Recovery plan summary |
| `CandidateRankTrace` | TotalCandidates, BestScore, BestText, BestSource, HasViableCandidate | Element ranking summary |

### 3. Agent Runtime API v1

Seven endpoints provide a complete agent runtime interface:

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/v1/health` | Runtime health check |
| POST | `/api/v1/task/preview` | Dry-run task preview (no execution) |
| POST | `/api/v1/task/run` | Execute a task |
| POST | `/api/v1/skill/search` | Search visual skill memory |
| POST | `/api/v1/skill/replay` | Replay a stored skill |
| POST | `/api/v1/risk/evaluate` | Evaluate action risk without execution |
| GET | `/api/v1/trace/{id}` | Retrieve execution trace by ID |

All endpoints follow the unified response format (see §4).

### 4. Unified API Response Format

Every API v1 response adheres to a single envelope:

```json
{
  "ok": true,
  "trace_id": "trace_20260530_120000",
  "decision": "ALLOW",
  "risk_level": "L0",
  "parser_mode": "rule_based",
  "grounding_score": 0.87,
  "actions": [],
  "verification": {
    "status": "Passed",
    "reason": "Typed text 'hello' found in after-state OCR",
    "confidence": 0.9
  },
  "error": null
}
```

| Field | Type | Description |
|-------|------|-------------|
| `ok` | bool | Overall success |
| `trace_id` | string | Execution trace identifier |
| `decision` | string | Risk gate decision: ALLOW / BLOCK |
| `risk_level` | string | Risk level: L0 / L1 / L2 |
| `parser_mode` | string | Parser used: rule_based / llm / none |
| `grounding_score` | double | Best element grounding score (0.0–1.0) |
| `actions` | array | List of executed steps |
| `verification` | object | Verification result (nullable) |
| `error` | string | Error message (nullable) |

```
┌─────────────────────────────────────────────────────────────────────┐
│                      AgentOrchestrator                              │

│  └─────────┬───────────┘                                            │
│            │ action plan                                             │
│            ▼                                                        │
│  ┌─────────────────────┐                                            │
│  │ ElementCandidateRanker │  ← OCR + UIA + Semantic + Layout        │
│  │ (IoU deduplication)    │                                         │
│  └─────────┬───────────┘                                            │
│            │ ranked candidates                                       │
│            ▼                                                        │
│  ┌─────────────────────┐                                            │
│  │   ActionExecutor    │  ← Executes top-ranked candidate           │
│  └─────────┬───────────┘                                            │
│            │ action result                                           │
│            ▼                                                        │
│  ┌─────────────────────┐                                            │

```
