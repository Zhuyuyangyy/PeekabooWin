## V0.13 Changes

### 1. Multi-Candidate Element Ranking

The `ElementCandidateRanker` evaluates multiple candidate elements for a given target using a weighted scoring system:

| Signal | Weight | Description |
|--------|--------|-------------|
| OCR | 0.25 | Optical character recognition text match |
| UIA | 0.30 | UI Automation property and control-type match |
| Semantic | 0.20 | Embedding-based semantic similarity |
| Layout | 0.25 | Spatial position and size heuristics |
| Context | bonus | Surrounding label / group context |

IoU-based deduplication merges overlapping bounding boxes before ranking, eliminating redundant candidates that refer to the same visual element.

### 2. Before-After Verification

The `ActionVerifier` confirms whether an executed action achieved its intended effect:

| Action Type | Verification Strategy |
|-------------|----------------------|
| `type` | Text content check — verify expected text appears in the target field |
| `click` | State change check — detect visibility, enabled state, or selection change |
| `focus` | Always pass — focus actions are inherently non-destructive |

Each verification produces a `VerificationResult` carrying a confidence score (0.0–1.0), allowing downstream recovery logic to act on partial successes.

### 3. Failure Recovery

The `RecoveryPlanner` provides six escalation strategies when an action fails verification:

| Strategy | Description |
|----------|-------------|
| **Retry** | Re-execute the same action with identical parameters |
| **Refocus** | Bring the target window/element to the foreground and retry |
| **Relocate** | Re-query the screen to find an alternative element matching the intent |
| **Replan** | Decompose the failed step into sub-steps and re-plan |
| **HumanReview** | Pause and request human intervention |
| **Abort** | Terminate the current task to prevent unsafe continuation |

When the maximum number of recovery attempts is exhausted, the planner escalates to the next strategy in the table above.

## Architecture

```
┌──────────────────────────┐
│   ElementCandidateRanker │  ← OCR + UIA + Semantic + Layout scoring
│   (IoU deduplication)    │
└───────────┬──────────────┘
            │ ranked candidates
            ▼
┌──────────────────────────┐
│    ActionExecutor        │  ← Executes top-ranked candidate
└───────────┬──────────────┘
            │ action result
            ▼
┌──────────────────────────┐
│    ActionVerifier        │  ← Before/after comparison
│   (VerificationResult)   │
└───────────┬──────────────┘
            │ pass / fail (confidence)
            ▼
┌──────────────────────────┐
│    RecoveryPlanner       │  ← 6-strategy escalation
│   (if verification fail) │
└───────────┬──────────────┘
            │ retry / refocus / relocate / replan / human / abort
            ▼
        ┌────────┐
        │  Done  │
        └────────┘
```
