# PeekabooWin V0.8 Technical Specification

> Skill-Guided Execution — Skills that actively guide VACP planning

---

## 1. Core Problem

V0.7 Skills could **bypass VACP** on high-confidence hits — skipping the vision pipeline entirely and replaying the stored ProcedureSteps directly.

This creates a reliability risk: a skill might be outdated (UI changed) but VACP never gets to verify. V0.7 evidence is only valid for demo scenarios with stable UIs.

---

## 2. Core Design Principle

**V0.8: Skill influences planning, never bypasses it.**

```
┌─────────────────────────────────────────────────────────┐
│  V0.8 Skill-Guided Execution Pipeline                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  User Task                                             │
│      │                                                 │
│      ▼                                                 │
│  ┌─────────────────────────┐                           │
│  │ STEP 0: Skill Search    │  ←── NEW in V0.8           │
│  │  Multi-dimensional      │                           │
│  │  scoring + policy       │                           │
│  │  filter                 │                           │
│  └────────────┬────────────┘                           │
│               │                                        │
│               ▼ Inject SkillHint into VacpRequest      │
│  ┌─────────────────────────┐                           │
│  │ STEP 1: VACP Execute     │  ←── NEVER SKIPPED       │
│  │  (with skill hints)      │                           │
│  │  SkillHint: suggested   │                           │
│  │  elements + action      │                           │
│  │  types bias ranking     │                           │
│  └────────────┬────────────┘                           │
│               │                                        │
│               ▼                                        │
│  ┌─────────────────────────┐                           │
│  │ STEP 2: Extract & Store  │                           │
│  │  (on success only)      │                           │
│  └─────────────────────────┘                           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

Key differences from V0.7:

| | V0.7 | V0.8 |
|---|---|---|
| On skill hit | Skip VACP, replay directly | Always run VACP with hints |
| Skill role | Execution short-circuit | Planning bias |
| Reliability | Skill may be stale | VACP verifies each time |
| Safety | Risk of wrong replay | Guarded by policy |

## 3. Multi-Dimensional Skill Scoring

### SkillMatchScore

```csharp
public class SkillMatchScore
{
    public double AppMatch;           // 0.0–1.0 wildcard pattern match
    public double TextMatch;          // 0.0–1.0 OCR text vs trigger conditions
    public double ActionSequenceMatch; // 0.0–1.0 task actions vs skill procedures
    public double RiskMatch;          // 0.0–1.0 riskLevel compatibility
    public double RecencyFactor;       // log-scaled usageCount
    public double Total;               // weighted composite
    public bool IsUsable => Total >= 0.6 && RiskMatch >= 0.5;
}
```

**Total = 0.30×AppMatch + 0.25×TextMatch + 0.20×ActionMatch + 0.15×RiskMatch + 0.10×Recency**

### Sub-scores

- **AppMatch**: wildcard pattern (`notepad*`, `*doubao*`, `*`) vs actual app name
- **TextMatch**: visible OCR text contains keywords from TriggerConditions
- **ActionSequenceMatch**: task verbs (`click`, `type`, `press`) overlap with skill ProcedureSteps
- **RiskMatch**: skill RiskLevel vs task risk inference. High-risk tasks (delete/transfer/send) block L0 skills
- **RecencyFactor**: log₁₀(usageCount+1) — more-used skills score higher

## 4. SkillExecutionPolicy (Hard Filters)

```csharp
public bool CanUseSkill(SkillSearchResult? candidate, string? taskText = null)
{
    if (candidate == null) return false;
    if (!candidate.Score.IsUsable) return false;

    // App pattern must match
    if (!MatchesAppPattern(candidate.Skill.AppPattern, candidate.Skill.AppPattern))
        return false;

    // High-risk tasks need skill with RiskLevel >= L1
    if (IsHighRiskTask(taskText) && candidate.Skill.RiskLevel == "L0")
        return false;

    return true;
}
```

**IsHighRiskTask**: true if task contains `delete`, `transfer`, `send`, `remove`, `destroy`, `drop`.

If any guard fails → skill is NOT used (but VACP still runs normally).

## 5. SkillHint (Injection into VACP)

```csharp
public class SkillHint
{
    public List<string> SuggestedElements;  // element labels from skill trace
    public List<string> SuggestedActionTypes; // action types from procedure steps
    public string PreferredRiskLevel;        // L0 / L1 / L2
}
```

Injected into `VacpRequest.SkillHint` before calling VACP. VACP's candidate ranking step can use these to:
- Boost grounding scores for `SuggestedElements`
- Prefer `SuggestedActionTypes` when multiple candidates are close in score

**Important**: SkillHint biases ranking, not execution. VACP still evaluates all candidates and can pick a different action if the hinted one doesn't verify.

## 8. CLI Commands (V0.8)

### skill-search
```bash
peekaboo-win skill-search --task "click the submit button" [--app notepad] [--visible-text "Edit Text"] [--window "notepad"]
```
Returns top-3 skill matches with score breakdown.

### skill-use-preview
```bash
peekaboo-win skill-use-preview --task "click the submit button" [--app notepad]
```
Shows whether a skill would be used as a hint (score >= 0.7), policy filter results.

### skill-execute-guided
```bash
peekaboo-win skill-execute-guided --task "click the submit button" [--app notepad]
```
Shows skill search preview + note that full guided execution goes through `agent` command.
