# PeekabooWin V0.9 — Multi-App Skill Generalization

## Goal
Skills learned on one application (e.g., Edge Doubao) can be safely transferred to similar applications (Notepad, Edge, generic dialogs) without dangerous cross-domain contamination.

## Architecture

```
SkillRetriever (V0.8)
    ↓ candidates
SkillTransferController  ← V0.9 CORE
    ├── SkillScopeValidator      ← NEW
    │       └── SkillScope
    ├── NegativeTransferGuard    ← NEW
    │       └── GuardContext / GuardResult
    └── AnchorMatcher            ← NEW
            └── VisualAnchor / AnchorCoverageResult
    ↓ decision
SkillHint or BLOCK
```

## New Components

### 1. WindowSignature
Fingerprints a window by: WindowType + InputMode + RiskDomain + ProcessFamily.

### 2. AppProfile
Persistent profile of an application's automation characteristics. Built from WindowSignature.

### 3. SkillScope
Defines where a skill can run: SupportedApps + RequiredAnchors + ForbiddenDomains + MinRiskLevel.

### 4. SkillScopeValidator
Validates SkillScope rules before skill injection.

### 5. VisualAnchor
Canonical UI anchor types with app-specific text variants.
- input_box / send_btn / ok_btn / cancel_btn / close_btn / edit_region

### 6. AnchorMatcher
Matches VisualAnchor specs against current screen OCR results.

### 7. NegativeTransferGuard
Blocks dangerous transfers even if SkillMatchScore ≥ 0.75:
- HIGH_RISK_VERB + L0/L1 skill → BLOCK
- Forbidden domain transfer → BLOCK
- external_ai_chat skill + payment/admin app → BLOCK

### 8. SkillTransferController
Orchestrates the full transfer decision pipeline.

## Transfer Decision Matrix

| Situation | Score≥0.75 | Action |
|-----------|-----------|--------|
| Safe transfer (Notepad→Notepad) | Yes | INJECT |
| High-risk verb + L0 skill | Any | BLOCK |
| Forbidden domain transfer | Any | BLOCK |
| Missing required anchors | Any | BLOCK |
| L2 skill on payment app | ≥0.75 | INJECT |
| Low score | <0.50 | BLOCK |
